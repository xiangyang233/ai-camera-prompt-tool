# AI 绘画镜头视角提示词工具需求档案

版本：0.1 草案

日期：2026-10-27

暂定项目名：AI Camera Prompt Tool

阶段：需求与仓库初始化，尚未实现软件。

## 1. 产品目标

帮助 AI 绘画创作者用中文选择镜头视角、景别和构图，查看直观示意，并获得可复制到绘图工具的提示词。主要用于人物立绘、产品展示、场景概念图和静态分镜。

首版暂定为桌面浏览器优先的轻量 Web 应用，在 Windows 的 Edge、Chrome 中运行。核心功能在浏览器本地完成，无需注册或模型 API 密钥。这些是便于启动开发的默认方案，后续可在本对话中调整。

## 2. 核心使用流程

1. 输入可选的主体描述，或直接生成镜头提示词片段。
2. 选择景别、水平视角、俯仰角；按需补充焦距、构图和景深。
3. 查看对应示意与中文解释，随选择实时更新提示词。
4. 切换中文或英文镜头措辞，编辑最终文本，一键复制或导出 TXT。
5. 将常用参数组合保存为本地预设，下次恢复使用。

## 3. 首版功能范围

| 优先级 | 功能 | 要求 |
| --- | --- | --- |
| P0 | 镜头参数选择 | 景别：大远景、远景、全身、中景、近景、特写；水平视角：正面、左前四分之三、右前四分之三、左右侧面、背面；俯仰角：平视、俯拍、仰拍、正俯视 |
| P0 | 可视化示意 | 使用原创简易人物或物体图形展示相机与主体位置、取景范围；随参数切换；明确这是构图示意，不是 AI 成图 |
| P0 | 提示词拼装 | 输出“仅镜头片段”或“主体描述 + 镜头片段”；提供中文和英文镜头词库；主体原文保留，不承诺离线翻译任意输入 |
| P0 | 预设与解释 | 至少 8 个预设，如正面肖像、侧面特写、低机位全身、俯视产品；显示术语简短解释 |
| P0 | 文本操作 | 结果可编辑、复制、导出 TXT、重置；修改参数时保留手动编辑内容，并提供显式重新生成入口 |
| P0 | 基础一致性 | 各参数单选且可不指定；避免重复和互斥词拼接；坐标与左右约定在示意图中可见 |
| P1 | 焦距和构图 | 可选 24、35、50、85、135mm 镜头描述，居中、三分法、对称构图，以及浅景深或深景深 |
| P1 | 本地保存 | 保存、命名、恢复和删除自定义预设；刷新后保留；支持 JSON 导入导出备份 |

P0 是第一轮可用原型的必需功能，P1 在第二轮补齐。首版不包含图片生成、模型部署、账户系统、云同步、付费服务和视频运镜。

## 4. 提示词规则

- 固定拼装顺序：主体 → 景别 → 水平方位 → 俯仰角 → 可选焦距 → 构图 → 景深。
- 左右方位以主体自身朝向为基准；示意图标注“主体左侧”和“主体右侧”。水平绕拍方位与画面倾斜分开，第一版不提供画面倾斜控制。
- 景别由用户明确选择；不能把焦距直接当成景别，也不能只凭相机距离判断取景范围。
- 第一版只输出通用自然语言，不添加某个平台专用权重、触发词或命令参数。后续模型适配器独立维护，并注明适用模型与版本。
- 同一输入在同一词库版本下产生相同结果；未选择字段不输出占位符。
- 通用文本用于表达镜头意图，不保证模型精确还原角度。需要精确控制的工作流可在后续结合专用 LoRA 或条件输入。

示例输入：主体为 `a traveler standing in a forest`；中景、正面、仰拍、35mm、居中、浅景深。

示例英文输出：

```text
a traveler standing in a forest, medium shot, front view, low-angle shot, 35mm lens, centered composition, shallow depth of field
```

中文镜头片段：

```text
中景，正面视角，仰拍，35mm 镜头，居中构图，浅景深
```

## 5. 页面与实现建议

页面分为参数选择区、镜头示意区和提示词输出区，预设入口放在顶部。窄屏改为上下排列，复制按钮始终易于找到。

建议使用 React、TypeScript 和 Vite；第一版用 SVG 或 Canvas 绘制简易示意，后续需要自由拖动相机时再引入 Three.js。词库与预设使用独立数据文件，提示词生成逻辑使用纯函数，收藏存入浏览器本地存储。当前只记录技术方案，不锁定依赖版本。

## 6. 验收标准

1. 不登录、不配置 API 即可完成选参数、查看提示词和复制流程。
2. 每个 P0 参数均有中文标签、英文映射和示意；至少 8 个预设能正确恢复对应选择。
3. 中文、英文输出与当前选择一致；不出现重复字段、空占位符或同维度冲突词。
4. 空主体可生成镜头片段；主体中的换行、标点和中文不导致界面报错。
5. 复制成功有反馈；剪贴板不可用时保留可选中的文本，并提示手动复制。
6. 手动编辑文本后切换参数，不会静默覆盖编辑；只有显式重新生成才替换。
7. P1 完成后，自定义预设刷新仍可恢复；无效 JSON 导入显示错误且不破坏已有预设。
8. 在 Edge、Chrome 桌面浏览器及 1280×720、390×844 两种视口检查主要流程，无阻挡操作的溢出。

## 8. 开发顺序

- M0：保存需求档案，创建 GitHub 仓库，提交初始文档。
- M1：实现 P0 参数选择、原创示意、通用中英文镜头词和复制导出，按验收项走查。
- M2：补齐 P1 焦距、构图、收藏和备份，完善交互与词库边界测试。
- M3：根据实际使用反馈决定是否增加 3D 自由拖动、批量分镜、模型专用格式或桌面打包。

优先验证“能否更快、准确地表达想要的镜头”；后续再评估是否需要接入 AI 润色或实际出图。
